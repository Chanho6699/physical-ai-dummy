# V2-clean vs V3 start-coverage: start/low-motion coverage comparison

Generated by `scripts/analyze_v2_vs_v3_start_coverage.py`. Read-only analysis only - no dataset
rename, no `meta/tasks.parquet` edit, no merge on disk, no training. Real cube x/y target
coordinates are not in either dataset's metadata and were not estimated.

Datasets:
- **V2** = `data/so101_cube_xy_grid35_v2_clean` - 35 episodes, 11,505 frames, 30fps.
- **V3** = `data/so101_cube_xy_start_coverage_v3` - 30 episodes, 9,822 frames, 30fps.
- **Combined** = literal in-memory concatenation of both (V3 episode indices offset by +1000 to
  avoid collision) - no merged dataset file was written.
- Both datasets' `meta/tasks.parquet` still store the single task string
  `"Pick up the cube and place it in the target area."` (unchanged, as instructed) even though
  V3's actual behaviour is Pick & Drop (release ~10cm above the bin).

Reused definitions (kept byte-identical to the two prior V2-clean audits so V2 numbers reproduce
exactly): movement threshold = cumulative per-joint displacement from the trajectory's own
frame-0 value >= 1.0deg sustained for >= 3 consecutive frames; static segment = frames before the
`observation.state` trajectory's own first-movement frame; `action` first-movement is measured
against **`action[0]`**, never `state[0]` (avoids a false trigger from the constant
leader/follower static action-state offset); chunk_size = 50; Safety Gate WOULD_CLAMP thresholds
from `configs/safety_gate.yaml` (shoulder_pan 4.58 / shoulder_lift 5.16 / elbow_flex 5.73 /
wrist_flex 4.01 / wrist_roll 1.15 / gripper 9.17 deg).

shoulder_pan/wrist_flex, not spread evenly across all 6 joints.

## F. Chunk future-motion correlation (chunk_size=50, static/low-motion observations only)

For each static-segment observation `t`, `chunk[k] = action[min(t+k, episode_end-1)]` for
k=0..49; deltas are `|chunk[k] - state(t)|`.

| joint | V2 chunk[0]\|d\| mean | V2 chunk-mean\|d\| mean | V2 %chunk-mean>WOULD_CLAMP | V3 chunk[0]\|d\| mean | V3 chunk-mean\|d\| mean | V3 %chunk-mean>WOULD_CLAMP |
|---|---:|---:|---:|---:|---:|---:|
| shoulder_lift | 0.614 | 20.50 | **99.7%** | 0.551 | 9.53 | **60.7%** |
| elbow_flex | 2.245 | 20.97 | **99.7%** | 2.089 | 10.02 | **61.7%** |

Combined: chunk-mean|d| shoulder_lift/elbow_flex = 13.89 / 14.37deg, 76.2% / 76.8% of static
frames still exceed WOULD_CLAMP on the full-chunk mean.

**The correlation weakened substantially but did not disappear.** V3 roughly halves both the
full-chunk mean magnitude (~20.5deg -> ~9.5-10.0deg for shoulder_lift/elbow_flex) and the fraction
of static-looking observations whose 50-step target chunk's mean magnitude would already trip
WOULD_CLAMP (99.7% -> ~61%). chunk[0] itself stays small and safe in both (confirms section D).
So: immediate action is small and safe in both V2 and V3, but a majority (~61%) of V3's
static-looking observations are *still* paired with a chunk whose average target is large - the
longer, more varied V3 holds give the model more (state, small-chunk-mean) examples than V2 did,
but they are not yet the majority even within V3's own static segment (each hold, however long,
is still followed by the same large pick-motion once it ends).

Full per-episode-per-joint table: `chunk_future_motion.csv`.

## G. Potential conflicting immediate labels

Method (state-distance-only screen, no image embedding / no model inference - see limitation
below): within each episode's own static segment (capped at 90 frames/episode), find cross-episode
frame pairs whose state is nearly identical (L2 across 6 joints <= 3.0deg - close to V2's own
median inter-episode start distance of 3.85deg, so it's a genuinely tight bar) and check whether
their immediate `action(t)-state(t)` differs a lot on shoulder_lift or elbow_flex (>= 2.0deg,
half the WOULD_CLAMP threshold).

| pool | close-state pairs found | of those, conflicting (>=2deg key-joint diff) | conflict rate |
|---|---:|---:|---:|
| within V2 | 137,313 | 19,044 | **13.9%** |
| within V3 | 75,486 | 4,982 | **6.6%** |
| cross V2<->V3 | 84,909 | 9,325 | 11.0% |

**Hold-time diversification did not make V3's internal conflicting-label rate worse than V2's -
it's actually lower (6.6% vs 13.9%).** This is a useful negative result: the concern in the task
brief (varied hold time -> near-identical observation, contradictory immediate label across
episodes) is a real, pre-existing property of this kind of dataset (V2 already has it, at a higher
rate, without any hold-time variation at all - it comes from ordinary near-duplicate start poses
plus fast movement onset making adjacent-in-time frames diverge quickly), and V3 did not amplify
it. The cross-dataset rate (11.0%, between the two) is what a merged V2+V3 training set would
inherit for state pairs that happen to straddle both source datasets.

Top-5 candidates (all currently within V2 - see `conflicting_label_candidates.csv` for the top 200
by `max_key_joint_diff_deg`, spanning V2, V3, and cross-dataset pairs):

| dataset_a/ep/frame | dataset_b/ep/frame | state L2 (deg) | shoulder_lift diff | elbow_flex diff |
|---|---|---:|---:|---:|
| v2_clean / ep18 / f0-4 | v2_clean / ep22 / f23 | 2.19 | 4.57 | 5.71 |

(Episode 18 frames 0-4 are all within 2.19deg L2 of episode 22's frame 23 - episode 18 is still
fully static there (delta ~0.09/-0.31deg) while episode 22 has already started moving by frame 23
(delta ~4.66/-6.02deg) - a genuine "same-looking state, different immediate label" case, but one
that predates V3 entirely.)

**Limitation (by design, not attempted here):** this screen is state-only. A pair flagged here is
not confirmed to also look visually similar (workspace/wrist camera frames were not compared - no
video decoding or embedding model was run, per the "저비용" / no-large-model-inference
constraint). Some flagged pairs may have visually distinguishable cube positions or arm
configurations that a policy could condition on even with near-identical proprioceptive state; a
follow-up frame-level check (even cheap, e.g. pixel/histogram difference on the first video frame
of each candidate pair) would be needed to separate "genuinely ambiguous from the policy's actual
input" from "state-only false positive."

## Answers

**1. V3가 기존 7.6% static/low-motion coverage를 실제로 개선했는가?**
예. 데이터 기반 정의로 V3는 13.5%로 거의 2배가 되었고, static-length가 15-34프레임의 좁은 분포에서
18-82프레임의 훨씬 넓은 분포로 바뀌었다 (섹션 C). 다만 65-episode 단순 결합 시 combined 값은
10.3%로, V2가 여전히 프레임 수에서 더 큰 비중을 차지해 V3 단독 수치보다는 낮게 나온다 (섹션 H).

**2. V3의 immediate GT action은 안전 threshold 안에 있는가?**
예, 확실히 안전하다. Start/low-motion 구간에서 action(t)-state(t)는 모든 6개 joint에서
WOULD_CLAMP 비율 0%이며 (V2는 elbow_flex에서 875개 중 1개, 0.11% 초과), p95/max 값도
shoulder_lift/elbow_flex 모두 V2보다 오히려 작다 (섹션 D). 즉 hold-time 다양화가 시작 구간의 큰
action을 재도입하지 않았다.

**3. V3가 start pose diversity를 실제로 늘렸는가?**
예, 크게 늘렸다. Frame-0 pairwise L2 median이 3.85deg -> 17.88deg (약 4.6배)로 증가했고, 이는
주로 shoulder_pan (std 0.85->9.56deg)과 wrist_flex (std 1.73->7.59deg)의 다양화에서 비롯된다.
다만 elbow_flex는 거의 그대로(0.32->0.24deg)이고 wrist_roll은 오히려 고정되었다(2.18->0.04deg) -
다양화가 6개 joint에 고르게 퍼지지 않고 특정 joint에 집중되어 있다 (섹션 E).

**4. static observation과 큰 future chunk movement의 correlation이 줄었는가?**
줄었지만 사라지지는 않았다. Chunk-mean|delta|가 WOULD_CLAMP을 초과하는 static-frame 비율이
shoulder_lift/elbow_flex 모두 99.7% -> 약 61%로 감소했고, chunk-mean 절대 크기도 절반 수준(약
20.5deg -> 9.5-10.0deg)으로 줄었다. 하지만 V3에서도 static-looking observation의 과반(~61%)이
여전히 WOULD_CLAMP을 넘는 평균 target chunk와 짝지어져 있다 - hold가 아무리 길어져도 그 이후에는
결국 같은 큰 pick 동작이 온다는 구조 자체는 남아있다 (섹션 F).

**5. hold-time 다양화 때문에 conflicting immediate labels가 심각하게 생겼는가?**
아니다, 오히려 V3 내부 conflict rate(6.6%)가 V2 내부 conflict rate(13.9%)보다 낮다. "유사한 state,
다른 immediate label"은 이 종류의 데이터셋에 원래 존재하는 현상이며(V2도 hold-time 변화 없이 이미
더 높은 비율로 갖고 있었다), V3가 이를 새로 만들거나 악화시켰다는 증거는 없다. Cross-dataset rate는
11.0%로 두 데이터셋을 합쳤을 때의 참고값이다 (섹션 G). 단, 이 스크린은 state distance 기반이며 영상
유사도까지 확인한 것은 아니라는 한계가 있다.

**6. V2+V3 65 episodes를 합쳐서 fresh training할 가치가 있는가?**
데이터 관점에서는 그렇다 - 65-episode 결합은 35-episode V2 단독보다 static coverage(10.3% vs
7.6%), start-pose diversity(median L2 12.71 vs 3.85deg), 그리고 static-observation의 안전한
immediate action(변화 없음, 여전히 안전) 모두에서 개선된다. 다만 이 분석은 (a) task 메타데이터가
여전히 실제 V3 동작(Pick & Drop)과 불일치한 상태이고, (b) chunk-mean 기준 WOULD_CLAMP 초과 비율이
combined에서도 76% 수준으로 여전히 높으며, (c) elbow_flex/wrist_roll 등 일부 joint는 V3에서도
다양화되지 않았다는 점에서, "그대로 합쳐서 학습"이 이전 overshoot 문제를 완전히 해결한다고 보장하지
않는다. 이 스크립트는 실제 merge/rename/training을 수행하지 않았다.

**7. 아니면 추가 수정/재수집이 필요한가?**
이 분석 결과만으로 판단하면: (a) task metadata를 실제 V3 행동(Pick & Drop, release ~10cm 위)에
맞게 수정하는 작업이 - 이번 분석 범위 밖이지만 - 언젠가 필요하고, (b) elbow_flex/wrist_roll의 start
diversity가 V3에서도 거의 늘지 않았으므로 이 두 joint를 목표로 한 추가 다양화가 있으면 chunk-mean
WOULD_CLAMP 비율(현재 61%)을 더 낮출 수 있을 것으로 보인다. 그 외에는 V3가 의도한 개선(coverage,
timing spread, start diversity, 안전한 immediate action, conflict rate 비악화)을 실측 데이터로
확인했으므로, 현재 65-episode 조합을 학습에 사용하는 것 자체를 막을 데이터 상의 이유는 이 분석에서
발견되지 않았다.
